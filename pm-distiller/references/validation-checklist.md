# Validation Checklist

## Distiller Output

- Inputs are explicit: user name, Confluence link, local folder.
- Source map distinguishes read evidence from unread external links.
- Distiller `SKILL.md` explicitly requires `skill-confluence` / `skynet-base confluence read/search` before inferring author style from Confluence.
- Confluence root/page was read; if it was empty or an index, Confluence search was run and relevant PRD/BRD/FRF pages were read.
- For Confluence-backed new PRDs/full drafts, the generated skill enforces "No Confluence source map, no full draft" when historical logic matters.
- Generated profile separates facts from inferences.
- Generated profile includes an author model with confirmed habits, inferred habits, historical logic modules, review preferences, recurring corrections, anti-patterns, and profile gaps.
- Generated profile explains how future user corrections become controlled preference updates instead of one-off PRD content.
- Profile completeness is assessed; if evidence is weak, the distiller outputs a profile preview plus missing evidence instead of claiming a complete personal copilot.
- Google Docs/Sheets/Figma/Jira are not claimed as read in V0.
- Frontend code inspection is optional and local-only.

## Generated Skill

- `SKILL.md` has clear trigger conditions.
- `SKILL.md` stays lean and links directly to all references.
- Reference files are one level deep.
- The default workflow is mode-based, not full-PRD-only.
- `new-prd-template.md`, `confluence-draft-workflow.md`, and `checklist-gates.md` are present.
- `confluence-discovery.md` is present and linked from `SKILL.md` or `source-router.md`.
- `author-model.md` is present and linked from `SKILL.md`; it separates author-specific knowledge from generic PRD best practices.
- `continuous-learning.md` is present and linked from `SKILL.md`; Learning Check mode exists.
- New PRD flow does not ask whether to create a Confluence page; it assumes the PM provides the link.
- New PRD flow asks for the Confluence PRD link when the user wants an initial Confluence draft and the link is missing.
- New PRD flow proposes an outline and waits for confirmation before full drafting.
- New PRD flow proposes and confirms a plan, Feature List, and outline before full drafting.
- Detail clarification is batched after outline confirmation and before Feature Details.
- Mandatory planning is explicit: every new PRD/full draft confirms plan, Feature List, and outline; `planning-with-files-zh` is used for new PRDs, multi-source Confluence tasks, source-heavy, browser-heavy, or multi-turn work.
- Initial draft validation flow includes Discovery Summary, Proposed Outline, outline confirmation, Detail Clarification, and Draft Readiness Check.
- Requirement Brief mode exists for insufficient source evidence.
- Auto Enrich writes additions into existing sections instead of creating unnecessary chapters.
- Review Board mode supports Blocker/Major/Minor severity and Pass/Conditional Pass/Fail verdict.
- New PRD template does not include Target Release or PRD Status by default.
- The first PRD metadata table uses one Jira/Epic traceability row; it does not duplicate `Request Info` and `Epic`.
- Scope defaults to `Markets`, `Tenant`, and `Channel` when channel scope matters.
- Standalone `In Scope` is not generated by default; `Out of Scope` is optional and only used for real exclusions.
- Feature List exists before Feature Details unless the PRD is tiny.
- Feature Details default to `Feature | Detail | UI/Diagram`.
- Long Feature Detail blocks follow the Chinese + `English Version:` rule.
- Confluence-ready drafts do not contain local-only relative links by default.
- Initial-draft Background guidance is concise English context, not detailed evidence dump.
- Scope avoids unnecessary role/module/system rows unless the source style requires them.
- The generated skill preserves the PM's repeated omissions and anti-patterns instead of adding generic PM boilerplate.
- The generated skill classifies user corrections before updating itself and avoids storing one-off PRD facts as durable preferences.
- Existing-flow optimization, pre-check, gating, and suppression PRDs put current/target behavior only in relevant Feature Detail rows/subsections.
- Feature Detail is table-first by default.
- Rollout, standalone Acceptance Criteria, and standalone Dependencies are optional late sections, not automatic chapters.
- Checklist tables include a `#` sequence column.
- Source routing includes editable vs read-only destinations.
- Quality checklist includes scope, goals/non-goals, FR/NFR, states, edge cases, metrics, rollout, and open questions.
- Validation passes with skill-creator `quick_validate.py`.

## Generator Script

- `scripts/create_pm_copilot.py --dry-run` works without writing files.
- Generated output passes `quick_validate.py`.
- Running without `--force` refuses to overwrite an existing skill.
- The script uses only Python standard library and local files.
